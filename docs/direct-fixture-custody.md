# Fixed direct fixture lifecycle control

This source component calibrates two disposable brokers. It does not launch
Kaferry, a test binary or a proxy, and cannot qualify a release. The fixed CLI
accepts repository, run ID, reviewed source head and input hash. It builds
nothing. A runnable setup/retention recipe is still incomplete.

Given a separately admitted native prebuilt controller and source-only export,
the controller reserves its private error outlet before further admissions. It
checks the actual native platform, UID, owned guest/kernel, fixed three-entry
HOME/PATH/LC_ALL environment, complete source catalog, root-owned installed Go
and its own running executable identity/build metadata. Machine ID, original
SDK archive digest and source catalog/head need independent external binding.
Adjacent JSON cannot prove the original compiler wait. The export has no Git
directory; clean VCS binding comes from the externally admitted build and actual
prebuilt image. Default caches and safeguards are unchanged.

When admitted, it calls direct Up once, reloads the exact typed state, requires
a same-run modern image proof with no Proxy/worker endpoints, then calls Down
once. A separate read-only helper inspects the two retained container IDs and
network ID for exact absence through the same private proof/executor/classifier.
It never removes anything or repeats cleanup. Missing identity, STOP, ambiguous
absence, failed evidence or cancellation leaves an incomplete retained result.
It cannot erase a failed cleanup by attempting another one.

Then, after all synchronous fixture command wait owners have returned, the
dedicated process performs one bounded adopted-child drain. Actual ECHILD is
required for the inner control. There is no signal workaround for a denied or
uncertain wait. Late cancellation/IO/close/publication failures reject success
through the actual return, including when a serialized candidate predates them.
Own final close and external custody remain unproved by this component.

The controller limit is300 seconds: existing Up240, Down30, final drain20 and
remaining admission/finalization margin; separate absence has5 seconds inside
that total. No user timeout/image/command/environment selectors are added.
The private result always requires an external actual wait and Mac readback,
and always sets ReleaseQualified:false. Prefixes and unresolved resources stay
retained after failure.

The source includes literal lifecycle/identity controls and real private-file
absence-reader controls. The first host target passed in5.558 seconds across
fixture/campaign packages; it is a harness test, not native fixture execution.
Fresh native setup, Kafka-only stock save, readiness, cleanup, outer parent
return, failed-prefix transport and Mac readback remain unmeasured. No old link
archive, literal image fixture or historical proof can authorize the new run.

`scripts/direct-fixture-guest-parent.py` implements the separate fixed parent.
It admits only `/home/labrunner/kaferry-direct-RUN/parent-input.json` and its
externally selected whole hash, a fixed prebuilt controller, native buildinfo,
source/input catalog and the exact owned guest. It reserves its own private
error sink before loading dependencies. Its sole child receives four compiled
flags and the same three-entry environment; no arbitrary command is accepted.

The parent reuses only platform/wait primitives from the fixed sibling
`native-check-guest-parent.py`, whose compiled SHA256 pin is
`0bd893b00de5ad6dec81497af4cdae003f065081a46303dd7aa0925e304f52ab`.
It loads already verified bytes under a fixed non-main module without bytecode.
The native-check binding, command and entry point remain uncalled. Its existing
360-second wait,30-second TERM,10-second KILL and2-second EOF bounds remain.
Actual sole wait, pidfd, capture/EOF and late cancellation facts stay separate
from inner fixture claims. Constructor uncertainty or denied waits never permit
another launch, wait or numeric-PID signal fallback. Nonzero/incomplete outcomes
retain available originals; no potentially live producer is read without the
original wait. Candidates cannot attest their own final close or custody.

## Separate image and fixed receipt custody

`scripts/snapshot-direct-fixture.py` accepts a run ID, source head and separately
authenticated custody-input hash. Source is only
`/home/labrunner/kaferry-direct-RUN`; outlet is the preowned Btrfs directory
`/home/labrunner/kaferry-direct-custody-RUN`, bound by its actual device/inode.
Native LinuxARM64/UID501 and Btrfs statfs are checked without changing the
filesystem, UID, namespace or safeguards. The tool reserves an exclusive
snapshot directory and its first private error sink before input reads.

The custody packet binds source/parent/input hashes and an external foreground
original. That original must record the actual Python-parent Wait and separate
stdout/stderr, plus independently reviewed producer quiescence. These remain
external claims needing authenticated caller evidence. A parent return, hash
or Boolean cannot prove that an inner producer stopped. Missing Wait/quiescence
refuses producer capture; no process scan, kill, retry or replacement sink exists.
Outer parent stdout/stderr retain early pre-sink failures separately from the
parent's own captured Go streams.

The selected originals are the fixed parent/build/input files, seven parent
private files, eight Go result files with optional interrupted result, typed
fixture state and broker-only private proof/command families. Only their literal
numeric command/operation naming patterns are selected. Unknown, missing,
linked, refused or changed originals retain bounded exact notices and force
incomplete capture. No arbitrary source tree, executable, Git directory or
unrelated resource is selected.

The same-run images.tar streams once from its exact nofollow stable source to
a separate output with a1MiB buffer and512MiB guard. The output closes/fsyncs,
then receives a separate streamed length/hash readback. Images never enter the
receipt tar or a whole-image Python object. Receipts.tar has a30MiB guard;
manifest/errors/result and two external records fit inside the separate32MiB
all-small profile. Source signatures are rechecked after capture. These are
admission/read/write guards, not quotas, allocated capacity or power-loss proof.
Late close failure rejects actual return even if an earlier candidate exists.
Every tar backend write, including footer/padding, reserves its allowance before
writing to the exclusive empty original. Partial, short or refused writes latch
that outlet and stop later members; uncertain bytes cannot disappear from the
size accounting. No retry, seek/reset or replacement writer is available.

`scripts/read-direct-fixture.py` verifies a private local copy of the five
snapshot outputs plus exact custody-input and external snapshot-foreground
records. The latter binds the actual snapshot Wait, return and final error/result
hashes. The reader uses only the fixed snapshot sibling's pure read/path helpers,
loaded from hash-bound bytes under a non-main namespace. It never invokes that
script's native admission or capture, extracts archives, launches processes or
publishes evidence. Independent review must authenticate the supplied packet,
code and foreground provenance before the result can support a runtime verdict.

Readback checks exact membership, identity/modes, streamed image bytes and all
receipt members/hashes. The fixed USTAR profile also requires canonical headers,
zero body padding, two real terminator blocks and the exact zero record padding
through physical EOF. Concatenated archives and truncated/hidden tails refuse.
It can verify retained bytes of a failed run while
keeping SourceCaptureComplete:false; successful custody is separate from
lifecycle success. Image-proof tuple agreement is only a comparison with the
controller claim, not a fresh image parser or Kafka readiness oracle.
ReleaseQualified and PublicationAuthorized remain false.

validation. Six new controls all failed on the unchanged old source in.354s:
two reached nonempty partial/short tar writes followed by later writes, and four
observed acceptance of rebound malformed archive envelopes. These failures are
retained. Actual over-limit growth was not measured by those small controls.

Other foreground/ELF/image values are literal fixture data with portable platform

Controls are wired into check.sh. Final frozen reviews/native checks, manual
